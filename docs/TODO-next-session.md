**Wallpaper-per-profile — DONE.** No `READ_MEDIA_IMAGES`/permission dialogs anywhere. `WorkspaceProfileManager.setAndSnapshotWallpaper(bitmap)` center-crops to the screen's aspect ratio (fixes off-center wallpaper bug) and snapshots per profile. **Silencer (DND) — DONE.** `app.lawnchair.silencer` package, ported from the old app's `DndController`. Tap the bell: if `ACCESS_NOTIFICATION_POLICY` isn't granted, opens the system settings screen to grant it; otherwise shows a menu (styled like the long-press menu's icon+label rows, `MaterialTheme.colorScheme.surfaceContainerHigh`) with presets (15m/30m/1h/until off) or, when active, "Turn off"/"+15 minutes". Session state (`until_millis`/`indefinite_active`) is stored in **its own plain `SharedPreferences` file** (`silencer_session`), deliberately NOT routed through `PreferenceManager2`'s DataStore — that file has reactive `onEach { reloadHelper.restart()/recreate() }` listeners on unrelated preferences (`hotseatMode`, `isHotseatEnabled`, `hotseatQsbProvider`) that fire on *any* write to the underlying DataStore, recreating the whole Activity mid-interaction. This was the root cause of two separate confusing bugs this session (icon/countdown not updating after an action; "can't turn it off/on") — if a future preference needs frequent writes from a hotseat/always-on-screen composable, use a dedicated SharedPreferences file, not PreferenceManager2, unless it truly needs cross-screen reactive observation.

The Silencer menu popup went through three iterations: a `Popup` anchored to the button's live-measured position (reproducibly shifted the whole hotseat controls row left a few dp for as long as it stayed open — confirmed via matched before/after screenshots, not a one-frame animation artifact; tried `PopupProperties(excludeFromSystemGesture = true)`, no effect) → a full-screen-positioned `Dialog` (broke tap-outside-to-dismiss and blocked all touches through to the hotseat, since its content Box covered the whole window) → **currently a plain centered `Dialog`** (`SilencerMenuPopup` in `DownshiftControlsUi.kt`), which is stable and correct but not positioned near the bell. Revisiting exact positioning (anchored near the button, no shift) is a nice-to-have, not urgent — the current centered version works correctly.

The countdown ticker (`rememberSilencerCountdownText`) is wrapped in `repeatOnLifecycle(Lifecycle.State.STARTED)`, deliberately, per the old app's own documented past incident (a DND countdown that ran a bare `while(true) { delay(N) }` with no lifecycle gate and drained battery in the background) — don't remove that gate.
